# Career data retention map

**Status:** Inventory, versioned sidecar viewing, a non-mutating copied-career dry-run transformer, parity tests, and real 20/50/100/500-season measurements are implemented. No live career data has been compacted, summarized, or deleted.

**Purpose:** Identify what can be summarized or exported to control save growth without changing simulation results or silently erasing the manager's story. This map is based on current producer/consumer code and active-career measurements; any compaction still needs migration, parity, export/recovery, and UI tests.

## Measured context

The latest generated no-club benchmark measured 3.43 MB at 20 seasons and 13.28 MB at 100 seasons. At 500 seasons, the original save was 62.25 MB; the dry-run candidate was 56.01 MB, and the full exact archive was 60.28 MB. Full replay without the checkpoint produced identical world-player pools for original and candidate at 20, 50, 100, and 500 seasons. The 500-season archive is close to the 64 MiB safety ceiling, and candidate-plus-archive uses more total storage than the original. These measurements describe active-save reduction, not total-storage savings.

## Order of safe work

1. Inventory documented and long-save size measurements recorded; automate size attribution in the stress fixtures.
2. **Export/recovery foundation implemented; compaction remains separate.** `src/career-archive.js` still reads version-1 exact sidecars and now exports/validates version-2 JSON bundles with SHA-256 record and manifest digests. Restore adds exact missing rows or replaces a matching compact stub only when its saved digest matches; conflicts, unknown years, and wrong career IDs are rejected. The Cloud locker writes a full pre-restore copy to the existing one-slot recovery location (replacing any prior recovery backup only after confirmation). This does not compact or summarize saves. Digests detect accidental corruption, not authorship.
3. **Compact format and dry-run workflow implemented for copied careers only.** `dryRunCompact` requires a caller-validated checkpoint, full-detail history, and an idle career; it returns a separate candidate and exact version-2 sidecar. It is not wired to save storage and does not migrate live careers.
4. **Read-only archive viewing implemented.** Version-2 bundles use SHA-256; version-1 imports remain supported. Exact rows attach in memory for the current session, and the season book has summary-only and exact-detail display. Tests now cover a checkpoint-free legacy career with a version-1 sidecar.
5. **Results-only consumer audit and parity implemented, migration still blocked.** World replay parity passed for copied 20/50/100/500-season generated careers; the club-managed fixture also preserved pool, cup draw, roster, manager biography, honours-based reputation, and trophy-room output. Club-profile and dossier history readers were checked against the retained summary fields. The 500-season archive was near the 64 MiB limit. This does not prove production browser-storage/recovery safety.
6. **Test-only transaction protocol implemented:** copied-save tests verify archive validation, explicit prior-backup replacement, full-backup write/readback, candidate replacement, rollback after write/verification failure, and recovery after injected interruption. The production migration and browser-storage wiring remain unimplemented. Transfer moves, kit history, club-world histories, and other records remain untouched.
7. Only after those gates pass, propose an explicit, versioned, reversible migration with pre-migration backup and exact restore. Do not change gameplay or tactical-trend parameters; seek separate authorization before any deployment.
